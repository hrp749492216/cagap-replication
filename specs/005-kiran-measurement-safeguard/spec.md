## User Scenarios & Testing

### User Story 1 - Understand compliance (Priority: P1)
Readers distinguish syntactic action compliance from a source-verified literal-only subset and from judge decisions.
**Independent test**: Every count reconciles to the strict population; literal successes require uncoerced original evidence.
**Acceptance**: New terminology throughout; historical terminology only in a provenance explanation; literal subset next to broad rates; predicate and judge counts, contributions, and within-path rates use explicit denominators.

### User Story 2 - Understand selection and scope (Priority: P1)
Readers see numerical full-inventory missing-outcome bounds in main results and know pooled results do not describe a typical hosted system.
**Independent test**: Recompute bounds from events and unresolved counts; Claude E1 includes both signs.
**Acceptance**: Report 522/11,520 versus 24/11,520 unresolved and Claude's 348 DISABLED unresolved, with pooled/affected-route E1/E2 bounds, clearly distinguished from confidence intervals and strict estimates.

### User Story 3 - Observe a dispatch safeguard (Priority: P2)
Readers see whether trusted confirmation prevents saved native calls reaching a synthetic handler.
**Independent test**: Same calls with/without gate; instrument inert handler entry; valid approval passes and absent/forged/stale/mismatched approval fails.
**Acceptance**: New replay outcomes separate from frozen output labels; no-confirmation assumption explicit; controls prove the gate can allow authorized calls; real users/adaptive attacks remain untested.

### Edge Cases
Ambiguous text, duplicate identities, missing source, type coercion, Boolean/numeric confusion, multiple actions, empty responses, forged/replayed approval must not silently count as validated or authorized.

- **Frozen estimands**: E1/E2 unchanged; literal subset descriptive; bounds use full inventories; replay estimates inert handler entry for identical saved calls.
